# НОВИЧОК — первые 90 дней нового сотрудника

**Демо:** https://iizexii.github.io/newbies-dashboard/ · **Код:** https://github.com/iizexii/newbies-dashboard

## Отчёт (15 строк, также в [REPORT.md](REPORT.md))

**Как понял слово.** «Новичок» — человек в первые 90 дней. Каждый третий ушедший не дорабатывает этот срок, значит, нужно заметить «выпадающего» новичка, пока он ещё работает, и сразу поручить кому-то конкретное действие.  
**Для кого.** Главный пользователь — HR. Ещё две роли: руководитель (получает поручения, ведёт своих новичков) и сам новичок (свои задачи и отметка «Я на работе»).  
**Что сделал.** Основной сценарий: HR видит новичка с высоким риском и причины с баллами (нет наставника, не было встречи 7/30/60, нет действий в задачах Б24, не взялся за задачу или застрял после срока, не отмечается на работе) → одной кнопкой ставит поручение руководителю → руководитель проводит встречу и назначает наставника → риск сразу пересчитывается.  
Вокруг сценария: вкладки по отделам с поиском, фильтрами и сортировкой; кабинеты руководителя и новичка; аналитика ранних уходов (где, когда, почему, у какого руководителя); админка сотрудников, руководителей и отделов.  
**От чего отказался.** От «ИИ предсказывает увольнение»: на выдуманных данных это была бы видимость модели. Риск считается по 11 прозрачным правилам с весами, каждое видно в карточке.  
От реальной интеграции с Б24 и настоящего входа: нет доступа к порталу. Роли переключаются в демо, данные подписаны как демо, запрос `tasks.task.add` для Б24 показан в интерфейсе.  
От сервера и БД: данные хранятся в браузере. Для проверки сценария этого хватает, для работы нет.  
**Что проверил.** 19 автотестов логики (`npm test`): рабочие дни, правила и пороги риска, виды просрочки, расчёт на дату увольнения, генератор данных, аналитика.  
В браузере (Chromium) прошёл сценарий HR → руководитель → новичок → HR на опубликованной версии, проверил добавление, правку и удаление в справочниках и все экраны на ширине телефона (375px). Ошибок в консоли нет.  
**Что не проверил.** Предсказывают ли сигналы реальные уходы: на синтетике аналитика показывает то, что я сам заложил в генератор, и это написано на экране. Не проверял другие браузеры, реальный объём данных Б24 и живых пользователей.  
Главное непроверенное допущение — что склад и магазины ведут задачи в Б24. Если нет, опорой для них станут отметки прихода, встречи и наставник. Рабочие дни считаются Пн–Пт, без смен и праздников.  
**Следующий шаг.** Уточнить у вас, кто из новичков работает в задачах Б24, и взять выгрузку за год. На ней проверить, какие сигналы действительно были у ушедших, и поправить веса.  
Затем подключить Б24 как приложение (вход, сотрудники, задачи, учёт времени, уведомления руководителю) с сервером и БД и запустить пилот на одном отделе.  
Инструменты: JavaScript без сборки и зависимостей, Node.js для тестов. Код написан с помощью ИИ (Claude).

Веб-дашборд, который помогает удержать новичков: HR видит, кто «выпадает» из адаптации и **почему**, руководитель получает конкретное поручение, а сам новичок — понятный кабинет со своими задачами и отметкой на работе.

Данные демонстрационные (синтетические, реальных людей нет). Интеграции с Битрикс24 в демо нет: структура данных и запросы REST подготовлены под неё.

## Три роли (демо-вход в сайдбаре, без пароля)

| Роль | Что видит и делает |
|---|---|
| **HR** (главный) | **Обзор**: 4 цифры, «кому нужно внимание сегодня», графики риска по отделам и приёма/уходов по месяцам. **Новички**: вкладки по отделам, поиск, фильтры, сортировка, карточка с причинами риска. **Аналитика уходов**: где, когда, почему, у каких руководителей. **Поручения** руководителям. **Админка**: справочники сотрудников, руководителей, отделов. |
| **Руководитель** | **Мои новички**: карточки команды — кто отметился сегодня, что тревожит, кнопки «Провёл встречу», «Дать задачу», «Назначить наставника». **Поручения от HR**: закрыть с комментарием, HR увидит результат. |
| **Сотрудник** (новичок) | **Мой день**: кнопка «Я на работе», календарь отметок, путь 90 дней, наставник, следующая встреча. **Мои задачи**: задачи из Б24 колонками «Новые / В работе / Завершено» с кнопками «Начать» и «Завершить». |

Всё связано: сотрудник завершил задачу или отметился → риск в карточке HR пересчитался. HR поручил → задача появилась у руководителя. Руководитель закрыл поручение → HR видит комментарий.

## Основной сценарий (≈ 1,5 минуты)

1. HR → **Обзор** → «Кому нужно внимание сегодня» → клик по новичку.
2. Карточка: причины риска с баллами → **«Поручить руководителю»**.
3. Переключиться на **Руководитель** (того же отдела) → поручение на месте → «Провёл встречу», «Назначить наставника» → риск падает.
4. Переключиться на **Сотрудник** → «Я на работе», в «Мои задачи» начать и завершить задачу.
5. Вернуться в HR → поручение выполнено с комментарием, риск новичка ниже.

## Как считается риск

Сумма баллов по правилам (только для работающих меньше 90 дней): 5+ высокий, 2–4 внимание, 0–1 норма.

| Сигнал | Баллы |
|---|---|
| За первые 3+ рабочих дня не поставлено ни одной задачи в Б24 | +3 |
| 5+ рабочих дней подряд без действий в задачах (3–4 дня) | +3 (+1) |
| Не отмечался на работе 2+ рабочих дня подряд (1 день) | +2 (+1) |
| Не назначен наставник | +2 |
| Не проведена встреча 7-го / 30-го дня (3 дня отсрочки) | +2 |
| Не проведена встреча 60-го дня | +1 |
| Не взялся за 3+ задачи, срок которых прошёл (1–2) | +2 (+1) |
| Начал, но «застрял»: 3+ задачи не закончены после срока (1–2) | +2 (+1) |
| Больше половины из 5+ завершённых задач закрыто позже срока | +1 |
| Завершено меньше 40% задач (при 5+ задачах) | +2 |
| Первая задача позже 3-го рабочего дня | +1 |

**Просрочка** делится на два сигнала, потому что руководителю нужно делать разное: «не взялся» — проверить, понимает ли новичок, что задача его; «застрял» — помочь разобраться. Совет попадает в текст поручения. Срок «сегодня» ещё не просрочка. Задача, закрытая позже срока, перестаёт быть просроченной; опоздания штрафуются, только если это система.

**Действие в задаче** — сотрудник сам начал или завершил задачу. Получение задачи — действие руководителя, его не считаем. Действие или отметка сегодня обнуляют соответствующую серию. Рабочие дни — Пн–Пт, без праздников и сменных графиков. «Нет действий в Б24» не значит «бездельничал»: на складе и в зале работа идёт и вне Б24.

Веса подобраны экспертно, а не обучены на данных. Сверить их можно на реальной истории увольнений (Аналитика → «Первые две недели»).

## Запуск

Нужен только Node.js 18+ (зависимостей нет):

```bash
npm start      # http://localhost:5173
npm test       # 19 тестов бизнес-логики
```

Публикация: подходит любой статический хостинг, сборка не нужна. Например, перетащить папку на https://app.netlify.com/drop или включить GitHub Pages из корня репозитория.

## Устройство

```
index.html, styles.css
src/app.js          сайдбар, роли, навигация, модальные окна, события
src/ctx.js          общее состояние и помощники
src/views/hr.js     обзор, новички, аналитика, поручения
src/views/card.js   карточка новичка
src/views/people.js кабинеты руководителя и сотрудника
src/views/admin.js  справочники
src/charts.js       графики на HTML/CSS с подсказками при наведении
src/risk.js         метрики и правила риска (чистые функции)
src/analytics.js    аналитика ранних уходов
src/data.js         генератор демо-данных (детерминированный, относительно «сегодня»)
src/store.js        localStorage + сдвиг дат, чтобы демо не «протухало»
tests/              node --test
```

Данные хранятся в браузере (localStorage): у каждого открывшего своя копия. «Сбросить демо» пересоздаёт данные. Демо-вход не является авторизацией: в рабочей версии роль определяется учётной записью Б24.

## Под интеграцию с Битрикс24

- сотрудники и дата выхода → `user.get` (или задачи HR-процесса приёма);
- задачи новичка → `tasks.task.list` с фильтром `RESPONSIBLE_ID`; «Начать» / «Завершить» → `tasks.task.start` / `tasks.task.complete`;
- поручение руководителю и задача новичку → `tasks.task.add` (payload виден в «Поручения»);
- отметка «Я на работе» → `timeman.open` (учёт рабочего времени Б24), если он включён на портале;
- вход → OAuth-приложение Б24: роль по должности и подразделению пользователя.
